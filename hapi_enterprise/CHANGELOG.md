# Промени в hAPI Enterprise

Тази версия: **0.69.5**. Пълната история е в [CHANGELOG.md](https://github.com/PasevSU/hAPI/blob/main/CHANGELOG.md).

## 0.69.5

Намаляване на дълга: всеки погълнат `catch` в издавания код вече казва **защо** е безопасен,
повредените метаданни дават разбираемо съобщение вместо `SyntaxError`, а миграцията на
хранилището не пада от заключен файл на Windows. Всички 160 теста минават.

### Празните `catch` вече са документирани

- 25 празни `catch` в `admin.js`, `cabinet.js`, `gateway-api.js`, `job-manager.js`,
  `retention.js`, `server.js` и `standalone.js` получиха конкретна причина
  (напр. „файл, изчезнал между readdir и stat, се прескача“).
- `scripts/bad-code-scan.cjs` приема празен `catch` **само** с коментар-причина поне 15 знака
  (`catch { /* … */ }`); `catch { }` и `catch { /* ok */ }` остават находки. Така правилото
  не изчезва, а изисква решение.
- Находките в сканера паднаха от 163 на 138, а в издавания код остават 16 (`json-parse`), всички
  в `try`/`catch` или с изричен резервен вариант.

### Повредени метаданни: ясна грешка вместо `SyntaxError`

- `sqlite-store.js` чете payload-а през `parseStored()`; при счупен JSON хвърля
  `CORRUPT_METADATA` (500) с обяснение кое е повредено и какво да се направи.
- Нов тест `tests/corrupt-metadata.cjs`: повредена база, повредена JSON-снимка, нормален път.

### Миграция на хранилището: устойчив rename

- `storage-migrate.js` прави финалното преименуване с няколко кратки опита при `EPERM`/`EBUSY`
  (на Windows защитна програма или индексатор може още да държи файл в новата папка).
  На Linux остава един `rename(2)`.

### Тестове

- `freePort()` вече помни дадените портове (две последователни извиквания не можеха да върнат
  един и същ номер) и оставя 1000 номера резерв под 65535, защото тестове смятат `port + N`.
- `tests/enterprise-lifecycle.cjs` рестартира на собствен `freePort()` вместо `port + 500`,
  което можеше да излезе извън диапазона (`ERR_SOCKET_BAD_PORT`).
