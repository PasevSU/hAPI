# HTTP компоненти (`hapi_enterprise/routes/`)

`server.js` беше ~3000 реда и 50 маршрута наведнъж — трудно за обслужване и за преглед.
Затова отделните дялове от API-то живеят тук, а `server.js` пази само рутирането и общото
състояние (база, портали, файлове, настройки).

## Договор

```js
module.exports = { create };
```

`create(deps)` връща `{ handle }`, а `handle({ req, res, url, parts, method })`:

- `true` — заявката е за този компонент и е приключена (отговорът е изписан);
- `false` — не е негова; следващият компонент я поема.

Зависимостите се подават изрично от `server.js`. Компонентът **не** чете `db`, портали,
файлове или настройки, освен ако не са му подадени — така границата се вижда в един ред.

Изключение, което се пази нарочно: ако заявката е за дяла, но пътят е непознат,
компонентът връща `404`, вместо да я пусне нататък (иначе съседен дял би я поел и
объркването щеше да е тихо).

## Правила

1. `require('../x')`, не `require('./x')` — от `routes/` пътят `./` сочи в `routes/`.
   Точно това счупи отчетите при изнасянето (MODULE_NOT_FOUND → 500).
2. Нов маршрут се слага в компонент, не в `server.js`: `tests/server-structure.cjs`
   държи таван на `server.js` и той **само се намалява**.
3. `Dockerfile` копира `routes/`; нов файл в тази папка влиза в образа без промяна.
4. Всеки компонент носи `'use strict';` и кратко обяснение защо е отделен.

## Изнесени досега

| Компонент      | Какво поема                                                         |
| -------------- | ------------------------------------------------------------------- |
| `reports.js`   | `/admin/api/v2/reports/{render,package,sign}`, `rfc3161` + `verify` |
| `generator.js` | `/admin/api/generator/templates` (четене, качване, изтриване)       |

| `settings.js`  | `/admin/api/settings`, `/connection`, база и архиви         | `runtime`, `backup*`               |
