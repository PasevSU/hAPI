## 3. Какво влезе във 0.69.35

Три обекта в Report Studio излизат от „планирано“ и вече наистина се печатат.

- **Подзаглавие** (`subtitle`) — заглавие на раздел. В PDF-а е истинско `h2`, а не уголемен
  параграф, така че структурата на отчета се вижда и от програми, които четат PDF-а.
- **Нова страница** (`pagebreak`) — ръчно прекъсване; следващото съдържание отива на нов лист.
  Тестът мери страниците спрямо същия манифест без прекъсването, тоест добавя се точно един
  лист (базовият шаблон понякога вече е на два).
- **Правна декларация** (`legal`) — собствен текст или, ако полето е празно, стандартната
  декларация на системата: казва какво се проверява по SHA-256 и че заверка на самоличност се
  извършва извън системата. Никакви обещания, които продуктът не изпълнява.
- Валидаторът (`report-manifest.js`) приема трите нови типа, обектният регистър ги води
  `ready` (9 → 12), а планираните намаляват от 8 на 5 (`data-block`, `logo`, `certificate`,
  `columns`, `dynamic`).
- Панелът: полета за трите блока в „Свойства“ и ред в A4 прегледа (`.pv-section`,
  `.pv-pagebreak`, `.pv-legal`).
- Нов договор `documentation/04_FUNCTION_SPECIFICATIONS/REPORT_OBJECTS.md` (INV-O1…O4) —
  включително правилото „един източник“: всеки `ready` тип е в схемата, всеки `planned` не е.

## 4. Как се проверява наново

```
node scripts/test-matrix.cjs          # пълният набор, от начало, до 5 опита
node scripts/build-release.cjs        # dist/
node scripts/verify-release.cjs       # S01–S21 върху готовия архив
npm run audit:gui                     # GUI + съвместимост + изданието
node scripts/release-status.cjs       # този отчет
```
