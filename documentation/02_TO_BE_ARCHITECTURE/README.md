# 02 · Архитектура „как трябва да бъде“ — индекс

Тази папка има два вида документи и объркването между тях е най-лесният начин да се
изгуби истината. Правилото е просто:

- **Нормативни** — казват какво ТРЯБВА да работи. Не се променят, за да паснат на кода.
- **Доказателствени** — казват какво РАБОТИ СЕГА. Генерират се или се проверяват от тестове.

| Документ | Вид | Какво отговаря | Проверка |
| --- | --- | --- | --- |
| `API_ARCHITECTURE_SPEC.md` (HAPI-ARCH-API-001) | нормативен | Какво трябва да работи: 23 точки, 12 инварианта, 4 договора, 14 сценария | — (чете се) |
| `API_ENDPOINT_REFERENCE.md` | доказателствен (генериран) | Всеки реален маршрут, метод, права, кодове за грешка | `scripts/api-reference.cjs --check`, `tests/api-reference.cjs` |
| `RUNTIME_EXECUTION_FLOWS.md` | доказателствен | Реалната последователност: GUI/QR → Gateway → backend → Storage/Manifest/Audit | преглед срещу кода |
| `ARCHITECTURE_COMPLIANCE_MATRIX.md` | доказателствен | Инвариант по инвариант: код + тест + статус; честен списък на липсите | `tests/scenario-matrix.cjs` |
| `OIDC_LOGIN.md` | нормативен + настройки | Вход през външен доставчик: какво се проверява и защо | `tests/oidc-login.cjs` |
| `EVIDENCE_PORTAL_V1.2_REVIEW.md` | преглед | Външен пакет срещу нашия код, файл по файл | байтова сверка |

| `DEPLOYMENT_MODEL.md` | преглед със решение | Add-on или Compose; защо PostgreSQL/Redis/worker не влизат; огледалото като шев | — (решение, не код) |
| `SYSTEM_ARCHITECTURE.md`, `DATA_MODEL.md`, `SECURITY_MODEL.md`, `STORAGE_ARCHITECTURE.md`, `CRYPTO_ENGINE.md`, `KEY_MANAGEMENT.md`, `SHARED_DATA.md`, `GUI_ARCHITECTURE.md`, `INTEGRATION_CONTRACTS.md`, `LINK_AND_STORAGE_CONTRACT.md`, `PGP_KEYRING_AND_WORK_FOLDER.md` | нормативни | Слоят по теми (сигурност, данни, крипто, GUI, интеграции) | по съответните тестове |

## Как се ползва

1. Четеш `API_ARCHITECTURE_SPEC.md` — това е законът.
2. Отваряш `ARCHITECTURE_COMPLIANCE_MATRIX.md` — виждаш къде законът е изпълнен и къде не.
3. Ако ред от §5 („липсва“) се затвори, той се мести в §5.1 с кода и теста, който го пази.
4. Ако кодът и спецификацията се разминат, **не се пренаписва спецификацията** — попълва се
   матрицата, защото тя е списъкът на това, което още не е направено.

## Свързани папки

- `01_AS_IS_ARCHITECTURE/` — какво има сега (каталог на модулите, дефекти, инвентар).
- `04_FUNCTION_SPECIFICATIONS/` — функционални спецификации по възможности.
- `06_TESTING/TEST_CASE_CATALOG.md` — кой тест кой инвариант пази.
- `07_RELEASE/` — гейтовете, през които минава едно издание.
