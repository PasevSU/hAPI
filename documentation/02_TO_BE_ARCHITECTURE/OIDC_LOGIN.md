# OIDC вход (Pocket ID, Keycloak, Authentik…) — как се включва

**Статус:** реализирано в 0.69.86 · **Код:** `oidc.js`, `routes/oidc.js` · **Тест:** `tests/oidc-login.cjs`

## 1. Какво прави

`/api/v1/auth/oidc/login` → пренасочва към доставчика → `/api/v1/auth/oidc/callback` →
проверява ID token и създава **обикновена hAPI сесия** + HttpOnly бисквитка `hapi_sso`.
Токенът не влиза в адреса (не остава в историята, логовете и `Referer`).

## 2. Настройки (среда, не `config.yaml`)

| Променлива | Задължителна | Значение |
| --- | --- | --- |
| `HAPI_OIDC_ISSUER` | да | Адрес на доставчика без наклонена черта накрая, напр. `https://pocket-id.local:1411` |
| `HAPI_OIDC_CLIENT_ID` | да | Клиентът, регистриран при доставчика |
| `HAPI_OIDC_CLIENT_SECRET` | не | Ако клиентът е поверителен (при PKCE публичен клиент не е нужен) |
| `HAPI_OIDC_REDIRECT_URL` | да | Точният адрес за връщане, напр. `https://hapi.example/api/v1/auth/oidc/callback` |
| `HAPI_OIDC_ADMIN_GROUP` | не | Групата, която дава роля `admin` (иначе влизането е само за четене) |
| `HAPI_OIDC_ALLOWED_GROUPS` | не | Списък със запетаи; празно = всяка група от доставчика |
| `HAPI_OIDC_GROUPS_CLAIM` | не | Име на claim-а с групите (по подразбиране `groups`) |
| `HAPI_OIDC_SCOPES` | не | По подразбиране `openid profile email groups` |
| `HAPI_OIDC_AUTO_PROVISION` | не | `1` = създава локален акаунт при първи вход; иначе 403 |

Без `ISSUER`, `CLIENT_ID` и `REDIRECT_URL` входът е **изключен** и двата пътя връщат `404`
(„почти работещ“ вход е по-лош от липсващ).

## 3. Какво се проверява (и защо точно това)

| Проверка | Срещу какво |
| --- | --- |
| `state` | съществува САМО на сървъра, харчи се веднъж, живее 5 минути |
| `nonce` | запазения за конкретния вход — токен от друг вход не минава |
| `alg` | САМО `RS256`; `none` и HS* са отказ (иначе подписът се фабрикува от клиента) |
| подпис | RSA-SHA256 с ключ от JWKS; непознат `kid` → еднократно презареждане (ротация) |
| `iss`, `aud`, `exp` | срещу конфигурацията, не срещу самия токен |
| PKCE | `S256`; `code_verifier` се проверява при `/token` |

## 4. Роля

Ролята идва от **групите**, не от потребителя: `HAPI_OIDC_ADMIN_GROUP` → `admin`
(скоупове `admin, read, download`), иначе `viewer` (`read, download`). Групи извън
`HAPI_OIDC_ALLOWED_GROUPS` → `403` и одит `auth.oidc.denied`.

## 5. Какво НЕ прави (честно)

- Не подменя локалните акаунти — те остават (`/api/v1/auth/login`).
- Не прави изход при доставчика (single logout) — изходът от hAPI е `/api/v1/auth/logout`.
- Не пази групите като история — в одита влизат само броят им, не имената.

## 6. Регистрация при Pocket ID

1. Pocket ID → **OIDC Clients** → нов клиент.
2. Callback URL: `https://<адрес-на-hAPI>/api/v1/auth/oidc/callback`.
3. Вземи `Client ID` (и `Client Secret`, ако е поверителен) → сложи ги в средата на add-on-а.
4. Създай група (напр. `hapi-admins`), добави потребителя в нея и я запиши в `HAPI_OIDC_ADMIN_GROUP`.
5. `APP_URL` на Pocket ID трябва да е адресът, по който САМИЯТ доставчик е достъпен за браузъра —
   иначе пренасочването обратно сочи към вътрешен адрес.
