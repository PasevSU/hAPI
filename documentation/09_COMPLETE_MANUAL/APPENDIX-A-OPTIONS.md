# Приложение А — всички опции на add-on-а

> Генерирано от `scripts/docs-manual.cjs`; **не се редактира на ръка**.
> Стойността в колоната „по подразбиране“ е точно това, което издание 0.69.204 доставя.

Общо: **44** опции.

| Опция | По подразбиране | Име в интерфейса | Какво прави |
| --- | --- | --- | --- |
| `token` | `(празно)` | Admin token (required) | Required at start. At least 24 characters, not a placeholder and not a repetition pattern. The add-on refuses to start without it (ADMIN_TOKEN_REQUIRED) and never generates one by itself. In secrets.yaml this value is named hapi_token, but Home Assistant does not expand !secret in add-on options — enter the value itself here. Do NOT reuse a Home Assistant long-lived access token: it also opens the whole HA API, so one leaked hAPI token would be a leaked Home Assistant. The log warns with ADMIN_TOKEN_LOOKS_LIKE_HA_LLAT when it detects that shape. |
| `pgp_path_public` | `(празно)` | PGP public key path (optional) | Full path inside the container, e.g. /homeassistant/_openpgpV6/public.asc. Optional: if left empty (or the file is missing) the add-on starts normally and PGP stays unavailable. |
| `pgp_path_secret` | `(празно)` | PGP secret key path (optional) | Full path to the passphrase-protected secret key, e.g. /homeassistant/_openpgpV6/secret.asc (private.asc works too). Needed for reading encrypted paths and for work-folder decryption. |
| `pgp_path_pass` | `(празно)` | PGP passphrase file path (optional) | Full path to the file that holds HAPI_PGP_KEY_PASS=..., e.g. /homeassistant/_openpgpV6/.env. Point it at .env, never at .env.example (the template has an empty value). |
| `pgp_key_pass` | `(празно)` | PGP passphrase (optional) | The passphrase itself, kept in /data/options.json. Takes precedence over pgp_path_pass. Never printed in logs and never returned by the API. |
| `pgp_encrypt_paths` | `false` | Encrypt internal file paths | Stores storagePathEnc (PGP-encrypted) instead of the plaintext path in db.json. Requires a loaded key: without one the add-on still starts and logs pgp.encryption.without-key, but the first encryption fails with PGP_SECRET_KEY_REQUIRED (503) — nothing is left looking encrypted when it is not. State is visible at GET /admin/api/pgp/keyring. |
| `pgp_encrypt_workdir` | `false` | Encrypt the portal work folder | Encrypts the file contents in the portal work folder (AES-256-GCM with a per-file key wrapped by PGP). Requires a loaded key. Without the key and passphrase the files cannot be read. |
| `username` | `(празно)` | Console user name (not used — leave empty) | Kept for old configurations only. No code reads it; sign-in goes through Home Assistant identity (user_roles / group_roles). |
| `password` | `(празно)` | Console password (not used — leave empty) | Kept for old configurations only. No code reads it. Do not store a real password here. |
| `db_name` | `Files` | Database and portal name | Name used for the first portal and for the database file. |
| `backup_folder` | `(празно)` | Backup folder | Folder for scheduled backups. A relative path resolves inside /share. |
| `backup_mirror` | `(празно)` | Backup mirror folder | Optional second location for the database backups (inside /share, /media or /config). Every copy is verified with SHA-256; a copy that does not match the original is deleted, so a broken mirror can never look like a valid backup. |
| `storage_mirror` | `(празно)` | Second copy of the files (folder or s3) | A folder (inside /share, /media or /config) or an address `s3://bucket/prefix?endpoint=…&region=…&lock=days`. Every upload is written there too, read back and compared with SHA-256 by POST /admin/api/storage/mirror/verify; a missing or damaged side is restored (`repair`). With `lock=days` the S3 objects are locked (Object Lock COMPLIANCE) and cannot be deleted while the period runs. |
| `s3_access_key` | `(празно)` | S3 access key (s3 mirror only) | Required when `storage_mirror` is `s3://…`. Without it the s3 target is refused at start instead of silently writing nowhere. |
| `s3_secret_key` | `(празно)` | S3 secret key (s3 mirror only) | Pairs with the access key. It is never printed in the log and never part of the mirror address. |
| `memory_limit_mb` | `1024` | Node heap limit (MB) | 1024 by default, the value verified against the running deployment. 0 keeps the Node.js default (about half of the container memory) and 256-384 is the safe range on a Raspberry Pi; the value is passed as --max-old-space-size. |
| `db_id` | `1` | Database id | Identifier used in composite DOCFLOW keys. |
| `profiles` | `(празно)` | Configuration profiles | JSON object or path with portal, folder and field definitions. |
| `public_domain` | `(празно)` | Public domain | External host name used in QR codes and portal links, for example pasev.asuscomm.com. |
| `public_gateway` | `true` | Public API gateway | Enabled by default in this distribution (container port 8088 NOT published in config.yaml, so it is reachable only through a reverse proxy on the same host). |
| `public_same_origin` | `true` | Same-origin URLs | Enabled by default: emit relative URLs because the API answers on the Home Assistant host and port. Off means absolute URLs with CORS. |
| `user_roles` | `{"pasev-admin":"admin"}` | User roles | Optional JSON map from Home Assistant identity to role. The key is matched against the ingress headers `X-Remote-User-Name`, then `X-Remote-User-Id`, then `X-Remote-User-Display-Name`. Admin is the default for every Ingress user, so use this only to demote, e.g. {"guest": "viewer"}. Roles: `admin`, `operator`, `viewer`, and the court roles `judge`, `prosecutor`, `clerk`, `expert`. Court roles only READ evidence and the chain of custody; the exception is `expert`, who may submit an opinion. An unknown role is rejected so a typo cannot grant access. In this distribution the map is pre-filled (the installation user → `admin`) — that is the value the add-on is tested with. |
| `group_roles` | `(празно)` | Group roles | Optional JSON map of group name to role for a reverse proxy that adds `X-Remote-Groups`. Home Assistant itself does not send group information, so this stays empty in a plain add-on installation. |
| `storage_location` | `share` | Storage location | Where documents and the database live. `addon_config` (default) is the add-on's own folder (/config inside the container) and is included in Supervisor snapshots; `share` is the shared Home Assistant folder (visible over Samba); `media` is the other shared folder. |
| `storage_subdirectory` | `hAPI/data` | Storage subdirectory | Subfolder inside the chosen location; `hapi_enterprise` by default, i.e. `/config/hapi_enterprise` for the default `addon_config` location. Up to three levels are allowed (e.g. `documents/hapi/data`). If the data lived in the old folder before the update, the add-on keeps using it and logs STORAGE_LEGACY_LOCATION instead of starting with an empty database. |
| `storage_mode` | `local` | Storage mode | local uses the mounted folder directly; ha_network requires an active Home Assistant network storage mount. |
| `storage_mount_name` | `(празно)` | Network storage name | Name of the Home Assistant network storage mount (only for ha_network). |
| `min_free_mb` | `1000` | Minimum free space (MB) | 1000 by default. Startup fails when less free space is available at the storage location, so a full disk cannot silently corrupt the audit trail. |
| `log_level` | `info` | Log level | error, warn, info, debug or trace. debug adds one line per HTTP request; trace is reserved for very verbose diagnostics. Files are written to logs/ in the add-on folder. |
| `config_dir` | `(празно)` | Rules directory | Folder with the access and export rule files. Leave empty to use /config/rules, where the built-in defaults are copied on first start and can be edited. |
| `evidence_portal_deploy` | `true` | Publish the QR evidence portal | Copies the Evidence View portal to `www/hapi/data` inside the Home Assistant configuration — `/config/www/hapi/data` as Home Assistant sees it, `/homeassistant/www/hapi/data` inside the add-on container — so HA serves it at /local/hapi/data/portal.html. The configuration folder is recognised by `configuration.yaml`; set `EVIDENCE_PORTAL_ROOT` only to publish somewhere else. The portal reads its data from an evidence API; it does not expose files by itself. |
| `tsa_enabled` | `true` | RFC 3161 timestamps | Enabled by default in this distribution. Without internet the request fails closed (breaker) and does NOT block startup. When off, the timestamp endpoints answer 409 and no tokens are created; nothing is ever faked. |
| `tsa_start_url` | `https://zeitstempel.dfn.de/` | START TSA URL | Time-stamp authority for the START boundary (default DFN). Must be an http(s) URL; the reply token is stored as a .tsr file under the storage folder. |
| `tsa_stop_url` | `https://timestamp.digicert.com` | STOP TSA URL | Time-stamp authority for the STOP boundary (default DigiCert). STOP stamps the closing digest: SHA-256 of the START digest and the START token fingerprint. |
| `sign_packages` | `false` | Sign export packages | Sign every export package (.zip) with the selected OpenPGP key by default. A key must be attached first in the console (Settings -> PGP keys). |
| `signing_key` | `(празно)` | Signing key | Fingerprint or key ID of the OpenPGP key used for signing packages and receipts. Leave empty to use the key selected in the console. |
| `encrypt_files` | `false` | Encrypt stored files | Encrypt new uploads at rest (AES-256-GCM with the admin key) by default. An explicit X-File-Encrypt header still wins per upload. |
| `portal_folder_copy` | `false` | Copy attached files into the portal folder | Off by default: attaching a file to a portal keeps it in the add-on data and does NOT create a folder in /share. Turn on to also place a copy with the original name in the portal folder (storage_root). Files in /share are uploaded from the portal folders panel, where you choose the folder yourself. |
| `portal_skin` | `classic` | Public portal skin | classic — the proven style (default, nothing changes). modern — the second skin: glassy cards, large typography, pill buttons and a card grid for files. Both use the same HTML — only the stylesheet behind the QR code changes. |
| `tls_cert` | `(празно)` | TLS certificate | Path to a PEM certificate (inside /config, /ssl or /share). Together with the key it makes the add-on serve its own listeners over HTTPS. |
| `tls_key` | `(празно)` | TLS private key | Path to the PEM private key that matches the certificate. Both options must point to readable files, otherwise the add-on refuses to start. |
| `visitor_ip_mode` | `hashed` | Sensors · IP mode | What is kept of a visitor address: hashed (irreversible hash, default), masked (network/16) or full (the full address — personal data). Empty means the default. The same value can be set from the console: Settings → Sensors. |
| `visitor_retention_days` | `90` | Sensors · record lifetime (days) | How many days visits are kept before they are deleted. 0 or empty means the default (90 days). The value can also be changed from the console. |
| `visitor_geoip_path` | `(празно)` | Sensors · geo database file | Absolute path to an MMDB (GeoIP) file used for the visitor country. Empty means no geo database: countries stay unknown and the other sensors keep working. network: 8099/tcp: Internal API 8088/tcp: Public API gateway |
