# Порталът, който показва файловете и данните (Evidence View)

Този документ описва **страницата, която получателят отваря по QR и вижда в нея файловете и
данните им** — какво показва, откъде взима данните, къде стоят файловете ѝ и какво още липсва,
за да работи с истински доказателства вместо с демонстрация.

Ако търсиш договора за публичната страница на портала `/p/<id>` (id, QR, резюме, адреси за
изтегляне), той е отделен и обвързващ:
[`PORTAL_PAGE_CONTRACT.md`](PORTAL_PAGE_CONTRACT.md). Тук е **Evidence View** — самостоятелният
пакет, който се публикува в `www/` на Home Assistant.

## Три различни страници — не ги бъркай

| Страница                                                         | Какво показва                                                               | Откъде взима данните                                                                | Статус                          |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------- |
| `/p/<slug>` — портален изглед на add-on-а                        | списък файлове, QR, резюме, изтегляне                                       | `GET /api/v1/p/<slug>/api.json` (генерира се от `api-registry`)                     | ✅ работи                        |
| `/portal.html?folder=<slug>` — страница на папката               | файловете в папката на портала с истинските им имена                        | `portal-folder.page()` → генериран HTML                                             | ✅ работи (0.69.63)              |
| **Evidence View** — `/local/hapi/data/portal.html?folder=<slug>` | дърво от папки и файлове с метаданни, хешове, режим на достъп, consent gate | `GET /api/evidence/<folder>/manifest` — **⏳ не е реализиран**; днес само демо данни | ✅ фронтенд + публикуване, ⏳ API |

Третата е различна по замисъл: тя е **самостоятелен статичен пакет**, който може да се сервира и
от друг сървър (reverse proxy), и не изисква панела на add-on-а. Затова данните ѝ идват по
отделен договор, а не от `api.json`.

## Какво има в пакета

Пакетът е `hapi_enterprise/evidence-portal/` — без зависимости, чист HTML + ES модули:

| Файл                   | Размер  | Какво прави                                                                                    |
| ---------------------- | ------- | ---------------------------------------------------------------------------------------------- |
| `portal.html`          | 355 B   | входната страница; зарежда `assets/app.js` като ES модул, `lang="bg"`, `referrer: no-referrer` |
| `assets/app.js`        | ~9.2 KB | дървото от папки/файлове, метаданните, състоянията на достъп, модалът, заявките към API-то     |
| `assets/consent.js`    | ~6.0 KB | Consent Gate: съгласие преди показване на съдържание                                           |
| `assets/style.css`     | ~4.7 KB | адаптивен корпоративен изглед                                                                  |
| `sample-evidence.json` | ~2.5 KB | **демонстрационни** данни (синтетични, не са доказателства)                                    |
| `README.md`            | ~4.9 KB | договорът на API-то и правилата за сигурност                                                   |

Демо-данните са нарочно **в корена**, а не в `data/`: папка `data/` се пропуска от експорта на
хранилището, а този файл трябва да е част от изданието (`evidence-portal.js` изрежда файловете
изрично).

## Какви данни показва (схема)

`sample-evidence.json` е примерът, по който фронтендът е построен:

```json
{
  "title": "Доказателства (демонстрация)",
  "items": [
    {
      "id": "communications", "type": "folder", "name": "1. Комуникации",
      "children": [
        {
          "id": "eml1", "type": "file", "name": "chat_log_2026-03-14.eml",
          "extension": "eml", "bytes": 1258291,
          "created": "2026-03-14T10:12:00Z", "modified": "2026-03-14T10:24:00Z",
          "sha256": "…", "access": "free", "protection": "high",
          "software": { "name": "Thunderbird", "license": "MPL-2.0" }
        }
      ]
    }
  ]
}
```

| Поле                  | Значение                   | Внимание                                                              |
| --------------------- | -------------------------- | --------------------------------------------------------------------- |
| `type`                | `folder` или `file`        | дървото се строи от `children`                                        |
| `name`, `extension`   | какво вижда човекът        | имената са данни от манифеста, не са доказателство                    |
| `bytes`               | размер                     | число от манифеста                                                    |
| `created`, `modified` | **твърдения** от манифеста | не са криптографски доказани дати — README на пакета го казва изрично |
| `sha256`              | хеш                        | **метаданни**, докато не се сметне и сравни с реалните байтове        |
| `access`              | `free` / защитен           | определя дали се иска парола/одобрение                                |
| `protection`          | ниво на защита             | показва се като състояние                                             |
| `software`            | с какво е създаден файлът  | описателно; не значи, че зрителят има лиценз                          |

**Това е важно и е записано в самия пакет:** датите и хешовете от манифеста са твърдения, докато
не се проверят. Порталът не бива да представя „създаден на“ като доказана дата.

## Адреси

| Форма                                        | Кога се ползва                               | Забележка                                                                                             |
| -------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `/local/hapi/data/portal.html?folder=<slug>` | стандартният адрес в Home Assistant          | HA сервира `<HA config>/www` на `/local/`                                                             |
| `/portal.html?folder=<slug>`                 | когато пакетът се сервира от собствен сървър | демо/тест                                                                                             |
| `/portal.html:<slug>`                        | „красив“ адрес                               | **не е HTML параметър**; изисква rewrite в reverse proxy до `/portal.html` при запазен оригинален път |

За третата форма reverse proxy-то трябва да пренапише пътя, без да губи оригиналния (пример с
Nginx има в `README.md` на пакета). Това е пример за рутиране, **не** готова защитена
конфигурация.

## Какъв backend изисква (⏳)

Фронтендът е готов, но за истински файлове му трябват два маршрута:

| Метод | Път                               | Връща                                                                            |
| ----- | --------------------------------- | -------------------------------------------------------------------------------- |
| GET   | `/api/evidence/<folder>/manifest` | **само разрешените** метаданни на папката и файловете, `items` в схемата по-горе |
| POST  | `/api/evidence/<folder>/access`   | `{ "fileId", "action": "preview                                                  | download", "password"? }` → `{ "url": "/api/evidence/<еднократен-токен>" }` само при успех |

Токенът трябва да е обвързан с конкретния файл и действие, с кратък срок, и да се проверява
отново при самото доставяне. Паролата и декриптирането — **на сървъра**, никога в манифеста.

**Статус:** тези два маршрута **не са част от hAPI** към 0.69.66. Днес:
`GET /admin/api/evidence-portal/status` и `POST /admin/api/evidence-portal/deploy` само
публикуват статичния пакет; страницата показва демо данни и **не тегли истински файлове**.
Когато API-то бъде реализирано, то влиза в
[`INTEGRATION_CONTRACTS.md`](../02_TO_BE_ARCHITECTURE/INTEGRATION_CONTRACTS.md) и получава ред в
[`TEST_CASE_CATALOG.md`](../06_TESTING/TEST_CASE_CATALOG.md).

## Правила за сигурност (от README на пакета — задължителни)

- **Никога** `folder` или `fileId` не се превръщат директно в път на файловата система.
  Използват се случайни непредвидими capability-та + списъци за достъп на сървъра.
- Slug-ът на папката **не е** автентикация. Публичната QR връзка е bearer capability, освен ако
  няма допълнителна парола или вход.
- Административните API-та остават на отделен origin/услуга; Evidence API-то не бива да стига до
  други пакети или частни ключове.
- Забрани: traversal, симлинкове, IDOR, MIME sniffing, изпълнение на HTML/JS от доказателства,
  течове през кеш. Задължителни: TLS, `no-store` за частните отговори, ограничение на честотата,
  лог на достъпите, срок на сесията.
- Read-only интерфейс **не е** граница за сигурност.

## Къде стоят файловете на портала

| Какво                  | Път                                                                         |
| ---------------------- | --------------------------------------------------------------------------- |
| Източник в хранилището | `hapi_enterprise/evidence-portal/`                                          |
| В образа               | `/app/evidence-portal/`                                                     |
| Публикувано за HA      | `<HA config>/www/hapi/data/` = в контейнера `/homeassistant/www/hapi/data/` |
| Адрес в HA             | `/local/hapi/data/portal.html?folder=<slug>`                                |

Публикуването е идемпотентно (копира се само при различни хешове), отказва симлинк на целта и не
гадае къде е HA конфигурацията: коренът се разпознава по `configuration.yaml`
(`evidence-portal.js`, `detectRoot`). Пълната инсталационна карта е в
[`installation-layout.md`](../08_USER_GUIDES/installation-layout.md).

## Прикаченият пакет (2026-10-23) срещу този в хранилището

Измерено с `git diff --no-index` между `hapi_enterprise/evidence-portal/` и прикачения архив:

| Файл                                                                                        | В хранилището  | В прикачения | Разлика                    |
| ------------------------------------------------------------------------------------------- | -------------- | ------------ | -------------------------- |
| `assets/app.js`                                                                             | 9 216 B        | **10 127 B** | +28 реда: `loadManifest()` |
| `assets/consent.js`, `assets/style.css`, `portal.html`, `README.md`, `sample-evidence.json` | същите размери | същите       | няма                       |

Какво прави по-новата версия на `app.js` (това е поведението, което документът описва):

1. **Първо съгласие** — `requireConsent()` се извиква преди зареждане на данни (Consent Gate);
2. `loadManifest()` вика `GET /api/evidence/<id>/manifest` с `credentials: 'include'` и
   `cache: 'no-store'`; невалиден манифест (без масив `items`) е грешка, а не празен екран;
3. ако API-то не отговори и `id === 'demo-evidence'`, пада към `./sample-evidence.json`, после
   към `./data/demo-evidence.json`; за всяка друга папка показва „Пакетът не е намерен или
   нямате достъп до него.“ — без да разкрива дали папката съществува.

> **✅ Направено в 0.69.67 (B5):** `assets/app.js` в репото вече има `loadManifest()` и пада
> към `./data/demo-evidence.json`, а `evidence-portal.js` публикува и `data/demo-evidence.json`.
> Двете се проверяват от `tests/evidence-portal-publish.cjs` (истинско публикуване, хешове,
> идемпотентност, поправяне на развален файл).
>
> **Честно за размера:** прикачената версия е 10 127 B, а тази в репото е **9 972 B** — байт
> по байт съвпадение не се твърди, защото прикаченият файл не е в хранилището. Твърди се
> поведението, което документът описва (съгласие преди данни, `loadManifest()`, fallback към
> `./data/demo-evidence.json` само за демо пакета, ясно съобщение за останалите).

## Какво още липсва (честно)

| Липсва                                                                            | Защо е важно                                                                          |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `/api/evidence/…` backend (manifest + access)                                     | без него порталът показва демо данни, не истински доказателства                       |
| Реално изтегляне/преглед на файл през портала                                     | днес демото умишлено не позволява теглене                                             |
| Проверка на `sha256` в браузъра срещу реалните байтове                            | хешът е метаданни, докато не се сравни                                                |
| Ограничение на честотата и лог на достъпите за Evidence API-то                    | изискване от README на пакета                                                         |
| Consent Gate в production поток                                                   | `assets/consent.js` е налице; трябва да се обвърже с реалния достъп                   |

Тези редове не се броят за готови, докато няма тест — същото правило като в
[`PGP_KEYRING_AND_WORK_FOLDER.md`](../02_TO_BE_ARCHITECTURE/PGP_KEYRING_AND_WORK_FOLDER.md#състояние-какво-е-готово-и-какво-не).
