# Договор за изпълнение: публична страница на портала (`/p/<id>`)

- **Статус:** задължителен (binding) от 0.69.20. Този документ е източникът на истина за
  това какво вижда посетителят след сканиране на QR кода и какво връща API-то зад него.
- **Обхват:** `hapi_enterprise/portal.html`, `portal.js`, `portal.css` и маршрутите
  `GET /api/v1/p/<key>`, `GET /api/v1/p/<key>/files`, `GET /api/v1/p/<key>/files/<id>/download`,
  `GET /api/v1/p/<key>/qr.svg`, `POST /admin/api/notify/dispatch`.
- **Приемане:** `tests/portal-page-contract.cjs` (нов), `tests/portal-page.cjs`,
  `tests/portal-api-qr.cjs`, `tests/qr-dispatch.cjs`, `tests/portal-rules-applied.cjs`,
  `tests/public-rate-limit.cjs`.
- **Промяна на договора:** изисква едновременно (1) редакция тук, (2) тест, който пази новото
  поведение, (3) запис в `CHANGELOG.md`. Без трите — промяната не е договор, а мнение.

## 1. Неподлежащи на обсъждане правила (INV)

| ID     | Правило                                                                                           | Защо                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| INV-1  | Страницата показва **идентификатора на портала** (`/p/<id>`), не само адреса                      | По id се разпознава порталът при обаждане, поддръжка, одит; slug-ът се променя, id-то — не |
| INV-2  | QR кодът на страницата кодира **самата страница** (`/p/<id>`), не JSON API-то                     | Телефонът трябва да отвори списък с файлове, а не суров JSON                               |
| INV-3  | Страницата **съобщава какво представлява порталът** и **колко файла** съдържа (брой + обем + вид) | „Цялостен портал“ без брой файлове не е информация                                         |
| INV-4  | Всеки файл показва **текста на адреса си за изтегляне**, който може да се копира                  | Линкът се препредава по имейл/чат; бутон без адрес не се препредава                        |
| INV-5  | Натискането на **„Изтегли“** стартира сваляне                                                     | Без него „линк за изтегляне“ е обещание, не действие                                       |
| INV-6  | Файл с `DISABLED` **не** показва бутон за изтегляне                                               | Забраненото не се предлага                                                                 |
| INV-7  | `KEY_REQUIRED` файл иска ключ и **не** слага ключа в адреса                                       | Ключът пътува в заглавка `X-File-Key`, не в URL/логове                                     |
| INV-8  | Съобщения се изпращат **само от администраторския канал**                                         | Публична страница, която праща съобщения, е спам машина                                    |
| INV-9  | Данните се вмъкват само с `textContent`/`replaceChildren`, никога през `innerHTML`                | Име на файл или описание не може да инжектира HTML                                         |
| INV-10 | Портален токен (`?portal_token=`) се запазва във всички линкове на страницата                     | Частен портал не бива да губи достъп при копиране на линк                                  |
| INV-11 | Публичните маршрути имат лимит на честотата **по клиент**; отказът е `429` с `Retry-After`        | Един скрипт не бива да дърпа един файл хиляди пъти, нито да заключи осталите посетители    |

## 2. Изисквания и приемане

| REQ       | Изискване                                                                                                      | Изпълнение                                                                     | Приемане                                                                                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PP-01** | Страницата извежда идентификатора на портала, с копиране                                                       | `#portal-id` + `#copy-id`, стойност от `GET /api/v1/p/<key>.id`                | тестът търси `id="portal-id"` в HTML и `portal-id` в `portal.js`                                                                                                        |
| **PP-02** | QR кодът е видим и води до страницата                                                                          | `#qr` ← `urls.qr` (`qr.svg` кодира `urls.qrTarget = /p/<id>`)                  | `portal-api-qr.cjs`: `qr.svg` = SVG(`/p/<id>`), `qrTarget` = `/p/<id>`                                                                                                  |
| **PP-03** | Резюме: вид, брой файлове, общ обем, обновено на                                                               | `#summary` + `#summary-list`, изчислени от `files`                             | тестът проверява текстовете за 0/1/N файла и обема                                                                                                                      |
| **PP-04** | Всеки файл показва адреса си за изтегляне като текст + копиране                                                | `.file-link > code` + бутон „Копирай“                                          | тестът проверява `/files/<id>/download` в `portal.js` и `.file-link` в CSS                                                                                              |
| **PP-05** | „Изтегли“ стартира сваляне                                                                                     | `FREE` → `<a download>`; `KEY_REQUIRED` → ключ + бутон; `DISABLED` → без бутон | тестът проверява `download` атрибут и липсата на бутон при `DISABLED`                                                                                                   |
| **PP-06** | „Цялостен портал“ се назовава изрично, с брой файлове                                                          | при `> 1` файл резюмето казва „цялостен набор от N файла“                      | тестът проверява формулировката                                                                                                                                         |
| **PP-07** | Опция „Изпрати съобщение“ (текст/SMS/имейл през HA notify)                                                     | `POST /admin/api/notify/dispatch` (`portalId`/`fileId`/`link`)                 | `qr-dispatch.cjs`: 200 + линкът е `/p/<id>`; 503 без HA; 400 при невалидна услуга                                                                                       |
| **PP-08** | Сигурност: CSP, `no-referrer`, `noindex`, без външни ресурси                                                   | заглавки в `server.js`, `<meta>` в `portal.html`                               | `portal-page.cjs`: CSP `img-src 'self' data:`; `blackbox-security.cjs`                                                                                                  |
| **PP-09** | Достъпност и език                                                                                              | `lang="bg"`, `aria-*`, skip-link, клавиатура                                   | `portal-page.cjs` проверява ids и `portal.js`                                                                                                                           |
| **PP-10** | `?portal_token=` се запазва във всички генерирани линкове                                                      | `withAuth()` в `portal.js`                                                     | тестът проверява `portal_token` в `portal.js`                                                                                                                           |
| **PP-11** | Лимит на честотата: `PUBLIC_RATE_LIMIT`/`PUBLIC_RATE_WINDOW_MS`; `Range` не се брои; отказът влиза в сензорите | `publicRateGate()` в `server.js`; `PUBLIC_RATE_LIMIT=0` изключва               | `public-rate-limit.cjs`: 5×200 → 429 + `Retry-After`; друг клиент → 200; админ → 200; `Range` → без лимит; след прозореца → 200; `RATE_LIMIT` в сензорите; `0` изключва |

## 3. Договор на данните (API)

### `GET /api/v1/p/<key>` (`<key>` = id **или** slug)

```jsonc
{
  "id": "41f9ca368ad37d0f4051bd9d",     // PP-01: идентификаторът, който страницата показва
  "slug": "demo",
  "title": "Документи по дело 2026-114",
  "description": "…",
  "visibility": "public" | "private",
  "fileCount": 3,                        // само видимите (listed !== false)
  "urls": {
    "landing": "/p/<id>",                // човешката страница
    "qrTarget": "/p/<id>",               // какво кодира QR
    "qr": "/api/v1/p/<slug>/qr.svg",
    "api": "/api/v1/p/<slug>",
    "manifest": "/api/v1/p/<slug>/manifest"
  },
  "contact": { "name": "…", "email": "…", "phone": "…" } | null
}
```

### `GET /api/v1/p/<key>/files?limit=N`

```jsonc
{ "files": [ { "id": "…", "name": "…", "size": 1234, "sha256": "…", "version": 1,
               "uploadedAt": "…", "accessMode": "FREE|KEY_REQUIRED|DISABLED", "listed": true } ],
  "total": 3, "hasMore": false }
```

### `GET /api/v1/p/<key>/files/<fileId>/download`

| Условие                                  | Отговор                                              |
| ---------------------------------------- | ---------------------------------------------------- |
| `FREE`                                   | `200` + байтовете, `Content-Disposition: attachment` |
| `KEY_REQUIRED` без/с грешен `X-File-Key` | `403 File key required` / `403`                      |
| `KEY_REQUIRED` с верен ключ              | `200`                                                |
| `DISABLED`                               | `403 Download disabled`                              |
| скрит (`listed:false`)                   | `404`                                                |

### `POST /admin/api/notify/dispatch` (PP-07, само администратор)

```jsonc
// заявка
{ "service": "notify.smtp", "portalId": "…", "fileId": "…"?, "title": "…", "message": "…", "target": "…"? }
// отговор
{ "sent": true, "status": 200 }
```

- `portalId` без `fileId` → линкът е `/p/<id>` (страницата).
- `portalId` + `fileId` → линкът е адресът за изтегляне на файла.
- без `SUPERVISOR_TOKEN`/`HAPI_NOTIFY_ENDPOINT` → `503 Notify dispatch disabled`.
- невалидна услуга (не `domain.service`) → `400`.

## 4. Точни формулировки на резюмето (PP-03/PP-06)

| Състояние      | Текст                                                                        |
| -------------- | ---------------------------------------------------------------------------- |
| 0 файла        | „Порталът … още не съдържа файлове.“                                         |
| 1 файл         | „Този портал съдържа 1 документ с общ обем 12 KB.“                           |
| N > 1 файла    | „Този портал е цялостен набор от N файла с общ обем X MB (…).“               |
| само забранени | допълнение: „Издателят е спрял изтеглянето на всички файлове.“               |
| има ключове    | допълнение: „Файловете с ключ се отварят само с ключа, издаден от издателя.“ |

Съществителните идват от вида на артефактите (`KIND_BY_EXT` → `NOUNS` в `portal.js`), а не
се твърдо кодират: документ/документа, снимка/снимки, архивен файл, медия.

## 5. Какво договорът НЕ обещава

- **ZIP пакет на целия портал от публичната страница.** Пакетът се прави от администратора
  (`POST /admin/api/packages`) и се изтегля през `/admin/api/packages/<id>/download`; публичната
  страница не обещава файл, който не съществува.
- **Изпращане на съобщение от посетителя.** Опцията е администраторска (PP-07, INV-8).
- **Показване на файлове с `DISABLED`** и на скрити файлове (`listed:false`).
- **Конкретни числа за лимита.** Стойностите по подразбиране (120 заявки/мин на клиент) са
  отправна точка, а не обещание: `PUBLIC_RATE_LIMIT` и `PUBLIC_RATE_WINDOW_MS` ги сменят, а
  `PUBLIC_RATE_LIMIT=0` изключва лимита. Обещано е само поведението при отказ (INV-11, PP-11).
