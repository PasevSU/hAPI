# ADR-0022: Всеки feature минава checklist-а на гъвкавост (§2.4/§9.1)

- **Status:** Accepted
- **Дата:** 2026-10-12

## Контекст
Feature-и, добавени „на твърдо“, създават технически дълг. Нужна е гаранция, че
всяка нова функционалност е изключваема, сменяема и тествана.

## Решение
Всеки feature преминава §9.1 checklist преди да се смята за готов:
изключване през config, заменяемост, интерфейс, събитие, миграция+rollback,
ADR документ и изолиран тест. Недовършените точки се записват в ADR-а на feature-а.

## Последици
- Плюс: предвидимост, по-малко „hard-coded“ зависимости.
- Минус: повече първоначална работа за всеки feature.

## Checklist за гъвкавост (§9.1)
- [x] Изключва се през config? — да, това е самият критерий.
- [x] Заменя се с алтернатива? — да, интерфейсите са изискване.
- [x] Има интерфейс? — да.
- [x] Излъчва събитие? — Event Bus + audit.
- [x] Миграция с rollback? — изискване.
- [x] Документиран в ADR? — да.
- [x] Тестван изолирано? — изискване.
