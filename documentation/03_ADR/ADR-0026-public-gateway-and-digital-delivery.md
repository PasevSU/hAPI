# ADR-0026 — Public API Gateway, файлово предоставяне и контрол на достъпа

- **Статус:** Приет
- **Дата:** 2026-10-20
- **Обхват:** home-assistant add-on, Windows Edition, Report Studio, File Delivery
- **Свързани:** ADR-0008 (GUI runtime), ADR-0021 (multi-tenancy / zero trust), ADR-0024 (unified v6),
  ADR-0025 (Report Studio)
- **Планове:** [`docs/plan/19`](../../docs/plan/19-file-delivery-export-manager-plan.md),
  [`docs/plan/20`](../../docs/plan/20-unified-plan-v7.md)

## Контекст

hAPI ENTERPRICE е Home Assistant add-on: администрацията се осъществява през Ingress, а
продуктът трябва да предоставя файлове и отчети на **външни** посетители и API клиенти.
Смесването на административния Ingress с публичните портали създава три риска:

1. публичен посетител получава достъп до административни маршрути или Supervisor API;
2. HA сесия/бисквитки се използват като публична автентикация;
3. „изтегляне“ се превръща в бутон без правила за презапис, цялост и одит.

Досега в репото имаше само частично решение: `fileMode()` в `server.js` с три режима
(`FREE`, `KEY_REQUIRED`, `DISABLED`) и директен download endpoint без централни правила,
без проверка на SHA-256 при запис и без отделен канал за достъп.

## Решение

1. **Два независими канала в един add-on:**
   - административен **Ingress** (`ingress: true`, `ingress_port: 8099`) — управление,
     HA сесия, административен одит;
   - **Public API Gateway** (`ports: 8088/tcp: null`) — публични портали и файлове,
     без HA сесия, отделна история на достъпа.
   Публичният порт **не се публикува автоматично** (`public.published: false`) и изисква
   собствен HTTPS домейн, различен от този на Home Assistant.
2. **Изолация е задължителна:** gateway-ят отказва `/config`, `/ssl`, `/backup`, `/addons`,
   `/admin`, `/hassio`, `/supervisor`, `/api/hassio`, `/api/services`, `/api/states`,
   както и `..`, `//`, абсолютни/UNC пътища и файлови системни корени. Достъпът до диск е
   ограничен до `storage.allowed_roots` (`/share`, `/media`).
3. **Отделна токен схема:** публичните ключове са `hapi_…`; HA JWT (`eyJ…`) се отхвърля като
   публичен ключ. Порталният ключ **не наследява** вътрешни права (`evidence.export`,
   `audit.export`).
4. **Централни правила за достъп** в един модул (`hapi_enterprise/download-access.js`):
   5 режима (`FREE`, `KEY_REQUIRED`, `AUTHENTICATED`, `PRIVATE`, `DISABLED`), 8 нива на
   йерархия (system → storage → portal → folder → file → user/role → token → session),
   сливане „най-строгата политика печели“, решение с пълен списък проверки.
5. **Видимост и достъпност са независими:** `public`/`hidden` × режим дава ясна матрица на
   поведението (показва се, изисква ключ, само информационно, недостъпен).
6. **Файловото предоставяне е контролиран процес** (`export-rules.js`, `export-manager.js`):
   12 режима на експорт, предвидимо име `RPT-YYYYMMDD-HHMMSS-CASE`, `PACKAGE_INDEX.json`
   с `path/size/sha256/kind/source/verified`, временен файл `.part` → flush → повторен
   SHA-256 → атомарно преименуване, state machine `QUEUED…COMPLETED` (+ `FAILED`,
   `CANCELLED`, `RECOVERY_REQUIRED`) и одитен запис за всяка операция.
7. **Правата се прилагат в backend-а повторно при всяка заявка.** GUI (`Export & Download
   Center`, `Public Gateway & Access`, `Public Access Test`) е интерактивен модел и не е
   контролен механизъм.
8. **Никакви фиктивни способности:** компресия, части, криптиране, лимити и възобновяване са
   отделни `capabilities` с `implemented: false`, докато не бъдат реализирани и тествани.

## Последствия

**Положителни**

- Публичният канал не може да достигне административни пътища или конфигурация на HA.
- Едни и същи правила се ползват от GUI и backend; тестът `export-config.cjs` пази
  конфигурационните файлове синхронни с кода.
- Доказателствените пакети винаги имат проверка на SHA-256 и индекс; презаписът е забранен.
- Всяко „не“ има машинно четим код на причината (`reason`), който влиза и в одита.

**Отрицателни / цена**

- Два listener-а и два одитни потока вместо един — повече конфигурация.
- Публичният домейн и HTTPS reverse proxy са извън add-on-а; без тях порталът остава недостъпен.
- IP ограниченията не са защита срещу подправен `X-Forwarded-For` (изисква доверен proxy).
- SHA-256 доказва идентичност на байтовете, не произход; произходът остава задача на
  RFC 3161/подписа.

## Отхвърлени алтернативи

| Алтернатива | Причина за отказ |
| ----------- | ---------------- |
| Публични портали през Ingress | Изисква HA сесия; смесва административен и публичен трафик |
| Един порт с префикс `/public` | Няма гарантирана изолация; грешка в маршрутизацията излага админ пътища |
| Права само в JavaScript | GUI не е граница за сигурност; лесно се заобикаля |
| HA long-lived token като публичен ключ | Дава достъп до Home Assistant API; несъвместим с публична употреба |
| Директен `res.sendFile` без проверка | Няма цялост, няма одит, няма контрол на колизии и презапис |

## Изпълнение

| Етап | Съдържание |
| ---- | ---------- |
| PG-0 / FD-0 | `export-rules.js`, `download-access.js`, `public-gateway.js`, `config/rules/*`, `config/schemas/*` |
| FD-1 | `export-manager.js` (state machine, verified copy, индекс, одит) |
| FD-2 / PG-2 | GUI модели: `ui/export-center.js`, `ui/public-gateway.js` |
| FD-3 | тестове `export-rules`, `download-access`, `public-gateway`, `export-manager`, `export-config` |
| PG-6 / FD-6 | реален gateway listener и административни endpoints (следващ етап) |
| PG-7 | HA allowlist адаптер, SMB reconnect, USB preflight, browser streaming |

Критерии за приемане: всички тестове зелени; публичният канал отказва административни и
конфигурационни пътища; HA JWT не се приема като публичен ключ; доказателствен пакет без
проверка е невъзможен; нито един GUI бутон не твърди трансфер, който не се извършва.
