# ADR-0020: Версиониране: schema/API/data/UI

- **Status:** Accepted
- **Дата:** 2026-10-12

## Контекст
Промени в схемите, API-то, данните и UI-то трябва да са съвместими назад, особено
за вече деплойнати инсталации.

## Решение
Версиониране на четири нива: API (`v2` текущо, `v1` legacy + Sunset header),
схеми (Registry версия), данни (migration + rollback) и UI (артефакти с версия).

## Последици
- Плюс: предвидими миграции, ясна deprecation политика.
- Минус: дисциплина при добавяне на breaking промени.
