## 0. Защо този план

Разговорът описва 13 панела, но реалната работа е в три неща:

1. **Портал** — създаване, режим на достъп, ключове, QR, таксономия, обединяване.
2. **Файл** — качване, преглед, версии, метаданни, местене, изтриване, споделяне.
3. **Управление** — потребители/права, задачи, настройки, хранилища, одит, копия.

Отчетът (Report Studio) е **четвърти** и зависи от първите три: той само чете
данните им. Затова е в края (F8), а не в началото.

## 1. Функционална карта

```
ПОРТАЛ (F1)                ФАЙЛ (F2)                 УПРАВЛЕНИЕ (F5)
├─ CRUD                    ├─ качване (hash)         ├─ потребители/RBAC
├─ режим FREE/KEY/DISABLED ├─ списък/търсене         ├─ настройки (7 секции)
├─ ключове (ротация)       ├─ преглед/thumbnail      ├─ задачи + прогрес
├─ QR (портал/файл)        ├─ версии                 ├─ хранилища/проверки
├─ таксономия              ├─ метаданни              ├─ диагностика/логове
├─ обединяване             ├─ преименуване/местене   ├─ одит (hash chain)
├─ видимост/брандинг       ├─ копиране/изтриване     ├─ резервни копия
└─ подписани URL           └─ шифроване/retention    └─ натоварване/лимити

ВИРТУАЛНО ХРАНИЛИЩЕ (F3, ✅)     ПУБЛИЧНО API (F4)        ОТЧЕТИ (F8, последно)
/topic/category/group/име      ├─ /api/v1/p/{slug}…     ├─ манифест
единствени пътища              ├─ /storage[?path=]      ├─ PDF
                               └─ токени/обхвати         └─ TSA (F7)
```

## 2. Модел на данните (референтен)

| Обект | Полета (минимум) |
| ----- | ---------------- |
| `portal` | `id`, `slug` (immutable-ish), `title`, `description`, `visibility` (`public`/`private`), `branding {logoUrl, accentColor}`, `files[]`, `keys[]`, `createdAt` |
| `file` | `id`, `name`, `size`, `sha256`, `uploadedAt`, `topic`, `category`, `group`, `tags[]`, `listed`, `encrypted`, `versions[]`, `accessMode` |
| `key` | `id`, `prefix`, `hash`, `scopes[]`, `createdAt`, `revokedAt` |
| `virtualPath` | производен: `/<topic>/<category>/<group>/<name>` (никога не се пази) |
| `audit` | `at`, `event`, `actor`, `payload`, `prevHash`, `hash` |

Правило: **порталът е единицата за достъп**, файлът наследява таксономията на портала.

## 3. Диалози и опции (това, което разговорът нарича „Опции / Качи / Преглед“)

### 3.1 Меню на файл (контекстно)

| Действие | Какво прави | Права | Състояние |
| -------- | ----------- | ----- | --------- |
| **Преглед** | PDF/изображение/текст/офис в панел | `file:read` | ✅ backend, 🟡 GUI |
| **Изтегли** | поток + Range | `file:read` | ✅ |
| **Версии** | списък, връщане към версия | `file:write` | ✅ backend |
| **Метаданни** | тема/категория/група/тагове | `file:write` | ✅ backend |
| **Преименувай** | ново име (без `/`) | `file:write` | ✅ backend |
| **Премести** | към друга тема/категория/група (виртуално) | `file:write` | ❌ ново |
| **Копирай** | в друг портал | `file:write` + `portal:write` | ❌ ново |
| **Изтрий** | меко (скриване) / твърдо (с одит) | `file:delete` | ✅ backend |
| **Сподели** | подписан URL с TTL или файлов ключ | `file:share` | ✅ backend |
| **QR** | QR към файла (не само портала) | `qr:write` | 🟡 частично |
| **Шифровай** | AES-256-GCM at rest | `file:write` | ✅ backend |

### 3.2 Диалог „Качи файл“

1. Drag&drop или избор; лимит `maxUploadMb`; позволени типове.
2. **SHA-256 в браузъра преди качване**, сървърът го преизчислява и сравнява.
3. Таксономия (тема/категория/група/тагове) — падащи списъци от съществуващите.
4. Прогрес на качването + резултат (hash, размер, време) в Центъра за прогрес.
5. При конфликт на име → `queue`/`first`/`skip` (настройка `conflictPolicy`).

### 3.3 Диалог „Настройки на портала“

- Име, slug, описание, видимост, брандинг (лого URL, акцент).
- Режим: `FREE` / `KEY_REQUIRED` / `DISABLED`.
- Ключове: създай (показва се **веднъж**), ротирай, отмени; обхвати.
- QR: портал + опция „QR за всеки файл“.
- Таксономия: добави/преименувай тема, категория, група; премахване само ако е празна.

## 6. Ред на изпълнение (защо така)

1. **F6-2 + F6-3** (Портали и Файлове в GUI) — това са панелите, с които се работи.
2. **F2-10 / F2-11** (преместване/копиране) — липсващата файлова логика.
3. **F1-8** (slug → мести API директорията) — коректност на хранилището.
4. **F6-5, F6-6, F6-9** (задачи, хранилища, копия) — управление.
5. **F4-4…F4-7** (токени, договор, SDK, webhooks) — публичното API като продукт.
6. **F7** (доказателства/TSA) → **F8-4** (отчет върху реални данни) → **F8-5/6**.
7. **F9** — опаковка, когато функционалността е стабилна.

**Отчетът е №6, не №1.** Дотогава Report Studio остава работещ прототип, но без
реални данни и без правна тежест.

## 7. Дефиниция за готово на всяка вълна

- Всяка задача: endpoint + GUI действие + тест.
- Никакви фалшиви данни в „готова“ функция (демо е ясно надписано).
- Всяко действие по файл/портал се одитира.
- `npm test` зелен; нов тест за всяка нова операция.

## 8. Рискове

| Риск | Смекчаване |
| ---- | ---------- |
| GUI става монолитен | един панел = един JS файл (`ui/*.js`) |
| Преместване чупи виртуални пътища | пътят е производен, не се пази |
| Ключове в localStorage | само `sessionStorage`, кратък живот |
| Отчет върху демо данни | F8-4 е блокер за „готов отчет“ |
| TSA доставчик | интерфейс + fallback „без печат“ |
