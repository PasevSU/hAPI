## 1. Виртуално хранилище — модел

```
/
└── <topic>/          „Дело 2026-114“
    └── <category>/   „Доказателства“
        └── <group>/  „Том 1“
            └── <name> protokol.pdf
```

Инварианти:

1. `virtualPath()` е единствената функция, която създава път.
2. Празните нива се пропускат; сегментите се санират (`\ / : * ? " < > |` → `_`,
   `.`/`..` → `_`, ≤ 120 знака).
3. Дубликат в една папка → `име (2).ext`; никога не се презаписва.
4. Пътят е детерминиран за даден набор файлове.
5. `..` или абсолютен път в заявка → `404`, без изход от дървото.
6. Физическият път (`DATA_DIR/...`) не се връща в публичен отговор.

Реализация: `hapi_enterprise/virtual-storage.js` (UMD), тест `tests/virtual-storage.cjs`.

## 2. API договор (за портал)

| Метод | Път | Връща | Статус |
| ----- | --- | ----- | ------ |
| GET | `/api/v1/p/{slug}` | метаданни | ✅ |
| GET | `/api/v1/p/{slug}/manifest` | списък + `sha256` + `path` + `storage` | ✅ |
| GET | `/api/v1/p/{slug}/files` | списък (филтри, пагинация) | ✅ |
| GET | `/api/v1/p/{slug}/files/{id}` | метаданни | ✅ |
| GET | `/api/v1/p/{slug}/files/{id}/download` | поток (Range) | ✅ |
| GET | `/api/v1/p/{slug}/storage` | корен: папки + файлове | ✅ |
| GET | `/api/v1/p/{slug}/storage?path=/…` | съдържание на папка | ✅ |
| GET | `/api/v1/p/{slug}/openapi.json` | генерираният договор | ✅ |
| GET | `/api/v1/p/{slug}/qr.svg` | QR към API-то | ✅ |
| POST | `/admin/api/v2/portals/{slug}/api` | създава `api/<slug>/` + препратки | ✅ |

Автентикация: `X-Portal-Key` (портал), `X-File-Key` (файл), подписан URL
(`expires`+`sig`). Администраторският токен не се ползва за публични пътища.

## 4. Дефиниция за готово

1. `node scripts/run-tests.cjs` → всички тестове зелени (**80/80**).
2. `GET /manifest` → всеки файл с `path`; `storage.url` → `/storage`.
3. `/storage` и `?path=/Тема` → 200; `?path=/../../etc` → 404.
4. `api.json`: `storage.virtual === true` + `scheme`.
5. `openapi.json`: `/storage` с параметър `path`.
6. GUI на `file://`: „Генерирай API“ → дърво, 5 препратки, сваляне на двата файла.
7. Никъде няма фалшив TSA токен/сертификат.

## 5. Рискове

- Голямо дърво → лимит/пагинация на децата (още не е нужно при текущите обеми).
- Unicode имена в URL → клиентът ползва `encodeURIComponent`.
- TSA доставчик → интерфейс с fallback „без печат“.
